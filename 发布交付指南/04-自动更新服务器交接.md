# 锐捷 Harness 自动更新服务器交接

用途：交给负责 1Panel、Nginx 和下载网页的模型或维护人员。客户端源码与服务端发布必须遵守本文件中的同一协议。

## 1. 本次目标

从锐捷 Harness `2.1.0` 开始启用应用内更新检查。`2.0.7` 等更早版本没有启用后台更新，无法通过服务器远程补上该能力；用户需要最后手动安装一次 `2.1.0`。从后续版本开始，已安装 `2.1.0` 的用户启动应用后即可收到新版本提示。

更新服务不需要数据库、额外后端或额外服务器。现有 Harness 静态服务在 `/data/code/codex/deepseek_app/site` 提供版本 JSON 和安装包，复用现有 `/harness` Ingress；不修改根路径 `/`、`codex_app`、13002 或任何 `codex-*` 资源。

## 2. 客户端已有能力

源码位置：

- `dsh-plugin-desktop/src/update-checker.ts`：检查版本、严格校验稳定版 SemVer。
- `dsh-plugin-desktop/src/update-download.ts`：下载安装包，限制最大 1 GiB，并校验 Windows PE 或 macOS DMG 基本格式。
- `dsh-plugin-desktop/src/updates.ts`：启动后定时检查、托盘手动检查、按版本避免重复提示。
- `dsh-plugin-desktop/src/electron-runtime.ts`：原生确认框、下载、打开安装包和 Windows 退出交接。
- `dsh-plugin-desktop/cordis.patch.yml`：`desktop-updates.config.enabled: true`，从 `2.1.0` 开始启用后台检查。

当前行为：

- 正式打包应用启动约 60 秒后检查一次，此后每 6 小时检查一次。
- 托盘菜单提供“检查更新…”，可由用户立即手动检查。
- 只有服务端版本严格高于当前版本才提示。
- 后台网络错误、无效响应和没有新版时保持安静，不影响应用启动。
- Windows：确认后下载安装程序，再询问是否退出应用并启动 NSIS 安装器；可覆盖升级，不要求用户先卸载。
- macOS：确认后下载并打开 DMG，再由用户把应用替换到 Applications。当前内部 DMG 未签名、未公证，因此不能承诺完全静默安装。
- 用户确认更新后，安装包自动下载到应用私有更新目录，不再要求选择保存位置；安装动作仍需用户确认。

## 3. 客户端固定访问地址

客户端目前固定访问以下 HTTPS 地址：

```text
GET https://gptauth.ruijie.com.cn/harness/api/desktop/version
GET https://gptauth.ruijie.com.cn/harness/api/downloads/windows
GET https://gptauth.ruijie.com.cn/harness/api/downloads/mac
```

生产发布源固定为 `gptauth.ruijie.com.cn` 的 `/harness` 独立路径。客户端、下载网页和服务器发布脚本必须保持一致；不要只修改网页按钮，因为应用不会读取下载页上的地址。

## 4. 服务端协议

### 4.1 版本接口

`GET /api/desktop/version` 必须返回 HTTP 200 和 JSON：

```json
{"version":"2.1.0"}
```

要求：

- `Content-Type: application/json`。
- 版本必须是规范的三段稳定 SemVer，例如 `2.1.0`、`2.1.1`；不能写成 `v2.1.0`、`2.1` 或预发布版本。
- 响应体不得超过 4 KiB。
- 建议设置 `Cache-Control: no-store, no-cache, must-revalidate`，并关闭 CDN 对此路径的缓存。
- 该版本号代表 Windows 与 macOS 当前共同可发布的稳定版本。

### 4.2 Windows 下载接口

`GET /api/downloads/windows` 可以：

1. 直接返回当前版本的 Windows x64 NSIS 安装包；或
2. 返回 302/307，跳转到该安装包的固定 HTTPS 文件地址。

当前正式文件命名规则：

```text
Ruijie-Harness-<version>-x64-Setup.exe
```

最终响应必须为 HTTP 200、非空，且文件小于 1 GiB。客户端会跟随重定向并检查文件具有有效的 PE 头。

### 4.3 macOS 下载接口

`GET /api/downloads/mac` 可以直接返回或重定向到：

```text
Ruijie-Harness-<version>-macOS-universal.dmg
```

最终响应必须为 HTTP 200、非空，且文件小于 1 GiB。客户端会跟随重定向并检查文件具有有效的 UDIF DMG 尾部。

### 4.4 当前静态托管实现

版本化文件由发布向导放在：

```text
/data/code/codex/deepseek_app/site/Ruijie-Harness-2.1.0-x64-Setup.exe
/data/code/codex/deepseek_app/site/Ruijie-Harness-2.1.0-macOS-universal.dmg
```

`publish-harness-release.sh` 会让两个 `/api/downloads/*` 文件成为对应版本安装包的同盘硬链接，因此不会额外复制一份大文件。下载网页与应用更新使用同一批产物，版本 JSON 永远最后更新。

`serve.json` 为版本接口设置 `application/json` 和禁缓存响应头，为下载接口设置 `application/octet-stream`。静态服务提供正确的 `Content-Length` 和断点续传；Electron 主进程请求不依赖浏览器 CORS。

## 5. 每版上线顺序

必须严格按以下顺序发布，版本接口永远最后更新：

1. 完成源码提交以及 Windows/macOS 构建和验收。
2. 记录两个安装包的文件名、字节数和 SHA-256。
3. 上传 Windows EXE 和 macOS DMG 到新的版本化目录。
4. 直接访问两个版本化文件，确认 HTTP 200、大小和 SHA-256 与本地产物一致。
5. 更新 `/api/downloads/windows` 与 `/api/downloads/mac`，确认它们最终下载到本次产物。
6. 更新下载网页并检查按钮。
7. 最后才把 `/api/desktop/version` 改为新版本。
8. 使用仍安装旧版的测试机等待自动检查，或从托盘点击“检查更新…”，完成一次真实升级验证。

禁止先提高版本接口再上传安装包。否则旧客户端会收到更新提示，但下载到旧包、空文件或 404。

当前服务器的实际操作统一使用发布向导，不手工编辑 `index.html` 或三个接口：

```bash
sudo su root
bash /data/code/codex/harness_deploy/publish-harness-release.sh
```

向导暂停后，在 1Panel 把同版本 EXE 和 DMG 上传到 `/data/code/codex/deepseek_app/upload`。确认两次 `y` 后，向导会自动完成第 3～7 步、备份旧站点并进行公网验证。只有显示 `Setup complete` 才算发布成功。

## 6. 2.1.0 首次启用的特殊步骤

1. 源码维护者先提交启用更新功能的 `2.1.0`。
2. 分别生成并验收 Windows EXE 与 macOS universal DMG。
3. 服务器维护者按第 5 节上传两个 `2.1.0` 产物，并把三个接口切到 `2.1.0`。
4. 网页明确提示旧用户手动下载安装 `2.1.0`；不要宣称 `2.0.7` 会自动升级。
5. 保留一台已安装 `2.1.0` 的测试环境。发布 `2.1.1` 时用它验证完整自动发现、下载和安装交接流程。

在真实 Harness 三个接口正式发布前，`2.1.0` 客户端会把 404 或网络错误静默处理，不影响启动。不得因此提前交付：必须在两个 `2.1.0` 安装包均已验收后用发布向导一次性上线，且版本 JSON 最后切换。

## 7. 服务端验收

服务器维护者完成后，应向源码维护者返回：

- 三个接口的实际 URL、HTTP 状态、响应头与最终重定向地址。
- 版本 JSON 原文。
- Windows EXE 和 macOS DMG 的远端字节数与 SHA-256。
- 网页下载按钮最终指向的地址。
- 1Panel/Nginx 中版本接口的缓存策略。

可先执行以下只读检查：

```powershell
Invoke-RestMethod -Uri 'https://gptauth.ruijie.com.cn/harness/api/desktop/version'
Invoke-WebRequest -Uri 'https://gptauth.ruijie.com.cn/harness/api/downloads/windows' -Method Head
Invoke-WebRequest -Uri 'https://gptauth.ruijie.com.cn/harness/api/downloads/mac' -Method Head
```

HEAD 仅用于运维检查；客户端实际使用 GET。若服务器不支持 HEAD，必须至少验证 GET 下载和最终文件哈希。

## 8. macOS curl 安装入口

仓库提供 `scripts/install-macos.sh`。网站应把该文件原样发布为：

```text
https://gptauth.ruijie.com.cn/harness/install.sh
```

建议响应设置 `Content-Type: text/plain; charset=utf-8` 和 `Cache-Control: no-cache`。发布后可使用：

```bash
curl -fsSL https://gptauth.ruijie.com.cn/harness/install.sh | bash
```

脚本会从 `/api/downloads/mac` 下载当前 DMG、校验 DMG、挂载、核对应用 bundle id，然后把应用安全替换到 `/Applications`。没有写权限时会由 `sudo` 请求本机管理员密码。脚本不会关闭正在运行的应用、不会清除 quarantine、不会关闭 Gatekeeper；运行前必须退出锐捷 Harness，首次启动未签名内部版时仍需在 Finder 中右键选择“打开”。

正式 DMG 必须是 universal 构建，同时包含 `x86_64` 与 `arm64`。终端安装命令和网页上的 macOS 下载按钮都使用 `/api/downloads/mac` 指向的同一份 universal DMG，不按架构拆分下载地址。

## 9. 当前安全边界与后续改进

当前客户端固定信任 HTTPS 域名，并校验下载内容是基本有效的 EXE/DMG，但尚未从版本接口取得并核对 SHA-256。Windows 内部包当前也未做 Authenticode 签名，macOS 内部包未签名、未公证。

这不阻止内部试运行，但正式扩大分发前建议继续增加：带 SHA-256 的发布清单、Windows 固定代码签名证书、macOS Developer ID 签名与公证。任何时候都不要为了更新方便关闭 TLS 或系统安全校验。
