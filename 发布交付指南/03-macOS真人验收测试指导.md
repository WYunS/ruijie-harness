# 锐捷 Harness macOS 真人验收测试指导

用途：交给完全不了解项目上下文的大模型或测试人员，对最终 DMG 安装出的应用做接近真实同事使用方式的验收，并给出可追溯的阶段放行或阻断结论。本文件只负责完成本轮验收、定位失败性质、输出报告和作出判定；产品源码、分支和重新打包属于获得用户确认后的下一轮工作，不能在本轮验收中直接执行。

## 1. 唯一位置与测试对象

- 唯一源码仓库：`D:\ChatGPT\RuijieDSH`
- 动态矩阵生成命令：`corepack yarn workspace dsh-plugin-desktop accept:mac-plan dist/mac-internal/acceptance-evidence [上次已验收提交]`
- 最终安装包验收命令：`corepack yarn workspace dsh-plugin-desktop accept:mac-installed <DMG所在目录>`
- 自动验收实现：`dsh-plugin-desktop/scripts/verify-mac-installed-app.mjs`
- 自动验收证据：`dsh-plugin-desktop/dist/mac-internal/acceptance-evidence`
- 产品版本来源：`dsh-plugin-desktop/package.json`

验收对象必须是本次最终 DMG 安装出的 `.app`，不能用开发模式、源码页面或旧 DMG 代替。开始时记录 DMG 路径、bytes、SHA-256、源码 commit、GitHub run、Mac 型号、CPU、macOS 版本、网络类型和测试账户。

## 2. 每次先生成“固定 + 动态”矩阵

每次验收都包含两部分：

1. **固定基线**：第 4 节全部执行，任何版本都不能删除。
2. **动态增量**：从上次已经完成真人验收的 commit/tag 到当前候选 commit 读取真实 diff；也接受用户直接提供“本版新增/修改/修复了什么”。两种输入同时存在时取并集，不能互相覆盖。

自动生成 Git 差异矩阵：

```bash
cd /path/to/RuijieDSH
corepack yarn workspace dsh-plugin-desktop accept:mac-plan \
  dist/mac-internal/acceptance-evidence \
  <上次已验收提交>
```

如果用户直接描述本版变化，把每一项追加到 `ACCEPTANCE-PLAN.md`。每项至少写明：`编号 / 功能或风险 / 变更依据 / 环境 / 操作 / 预期 / 证据 / 结果`。

动态扩展规则：

- 侧栏变化：追加 Files、标签关闭/恢复、收起/展开、Office、PDF、图片和浏览器相邻回归。
- 打开目标或面板路由变化：追加“先激活下栏，再分别从对话/Agent 与下栏内部打开”的来源归属回归；对话来源固定右栏，下栏内部主动点击固定下栏。
- 模型或推理变化：追加默认模型、新旧会话、已有上下文、推理强度、普通对话、图片和文档理解。
- 时间、时区或其他模型可见运行时上下文变化：追加当前日期与星期直接问答、基于“今天”的搜索词、已有与新会话、完全重启，以及浏览器时区与系统时区证据。
- 登录或凭据变化：追加首次登录、回调页、退出重登、关闭重启、升级保留登录。
- 浏览器或 WebSearch 变化：追加 HTTP/HTTPS、同 URL 连续两次、返回/前进、`target=_blank`、家庭网络与公司网络。
- 浏览器读取、搜索供应商、降级或计费变化：追加 `browser_search` 右栏展示与已加载页面机器证据同步、`browser_open` 读页、用户在右栏内继续点击后的 `browser_read_current`、独立 `web_search`、供应商失败时的本地读页降级和密钥泄漏检查；没有服务端计量证据时不得宣称已从用户总额度扣费。
- 存储、profile 或迁移变化：追加全新数据目录、保留旧数据升级、删除后重建、设置和插件持久化。
- 会话删除、重命名或编辑交互变化：追加应用内删除确认、删除后立即键入、新建文件夹、会话/工作区重命名，以及可编辑区域原生右键剪切/复制/粘贴；不得用截图或切换页面恢复焦点后再判通过。
- Office、PDF、附件或 OCR 变化：追加中英文文件名、文本型与扫描型 PDF、图片理解、损坏文件、超限文件。
- 自动更新、版本接口、下载地址或 curl 安装脚本变化：追加同版本无误报、发现新版本、拒绝后不反复打扰、托盘重试、私有目录下载、DMG 打开、覆盖后数据保留，以及 curl 首装/覆盖和 Gatekeeper 边界。
- 新运行时代码无法映射到现有用例：标为 `manual-blocking`，先补验收项再继续。

完成条件：固定基线完整保留，本版每项变化都有正常路径、关键异常路径和重启/升级路径；矩阵在操作前冻结并保存。

真人验收的功能清单以“上次已验收版本到候选 commit 的源码差异、用户明确说明、本地开发版已确认行为”三者并集为准。测试者必须在最终 DMG 安装出的 `.app` 上按相同用户操作证明每项新功能存在，不能因为源码测试、本地开发版或 `win-unpacked` 已通过就把安装物标为通过；安装物缺少任一当前本地功能，应记录为产品/打包失败并影响阶段判定。

## 3. 先审查自动验收证据

GitHub macOS runner 会挂载 DMG、复制最终 `.app`，在隔离的 `DSH_HOME` 和 Electron userData 中执行真实 UI 操作。先检查：

- `ACCEPTANCE-PLAN.md`、`acceptance-plan.json`
- `ACCEPTANCE-REPORT.md`、`acceptance-report.json`
- `first-launch.png`、`first-launch-exercised.png`
- `restart.png`、`restart-persisted-ui.png`
- 对应 stdout、stderr 和 failure 截图

自动基线必须证明：

- 安装副本启动并进入真实工作台，窗口尺寸正常，不出现旧新手引导。
- 模拟 OAuth 登录成功，重启不重复授权。
- 自动选择隔离工作区并创建会话。
- 默认模型显示 `deepseek-v4-flash`，推理强度显示 `low`。
- 通过 UI 切换语言，偏好写入 `DSH_HOME/settings.yaml`，重启后保持。
- 侧栏可收起、展开、关闭 Files 标签并重新打开。
- Word、Excel、PPT、PDF、PNG 测试夹具能从 Files 中打开到对应预览器。
- 内置浏览器能打开 HTTPS 页面，不能出现 `ERR_SSL_PROTOCOL_ERROR`、证书错误或错误页。
- 模拟未完成授权时，等待窗保留 macOS 原生左上角交通灯且没有 Windows 右上角“×”；自动化实际关闭窗口后，本次启动结束且不会立即重弹。测试必须观察窗口生命周期，不能用源码字符串或控件存在代替点击结果。
- 最终 `.app` 的 profile、直接生产依赖和物理运行树都包含且只启用一份时间上下文；使用确定性时钟夹具时，注入内容中的当前日期、星期、IANA 时区和相对日期规则与夹具一致。真实模型是否遵循它仍留给真人步骤 4.2。
- “通用设置”顶部能展开“界面外观（颜色、壁纸与透明度）”；首次启动时气泡使用当前浅色/深色主题的原版颜色，用户主动修改主色后气泡跟随，重启仍保持；点击“一键恢复默认”后撤销颜色覆盖并回到当前主题的原版气泡，模拟登录、会话、工作区和 IM 配置不被清空。
- 左侧栏账号/额度、“IM机器人”、设置的顺序和对齐符合固定基线；点击“IM机器人”直达“插件 → IM机器人”。九渠道入口存在；不进入 IM 设置静置 60 秒时，没有浏览器、授权窗、二维码、外连或重复凭据提示。真实平台扫码、消息和会话接续仍由真人步骤 4.6 验证。
- 可控夹具中主搜索或普通工具失败、备用方式成功时，任务继续完成；主“对话”视图不出现中间失败行、红点、黄灯、红/黄错误文字或 `Error` 技术文本，“轨迹”和日志仍保留完整失败详情。全部合理路径失败时才出现原有红色终局错误。WhatsApp 错误夹具必须实际触发“生成二维码”，断网或无效代理时 `.app` 仍存活、IM 页面仍可操作，并显示可读错误；不得出现 `ReferenceError`、`invalid_union`、`invalid_value` 等内部异常或 RPC JSON。
- 最终 profile 中自动更新 row 已启用；正式 `.app` 使用固定 HTTPS 版本与下载地址，更新目标位于 Electron userData 的私有 `updates` 目录。开发模式因 `app.isPackaged=false` 不执行下载安装，不能用开发版截图冒充更新验收。

自动通过只能称为“已自动验证的 Mac 候选包”。模拟服务不能证明真实公司账号、真实模型语义理解、真实 WebSearch 或公司网络可用，这些项目必须继续真人测试。

### 3.1 自动验收脚本的稳定编写规则

本节是本次 2.0.8 多轮失败后形成的固定规则。新增动态用例必须沿用，不能为单个页面临时堆叠脆弱点击：

1. 每一步先定义可观察完成条件，再写操作；点击成功不等于功能成功。浏览器要等真实页面加载，文件要等对应预览器出现，设置要同时核对 UI 和持久化文件。
2. 临时工作区写入产品存储前使用 `realpathSync`。macOS 的 `/var` 通常会解析成 `/private/var`，路径字符串不一致不代表产品工作区功能失效。
3. 控件定位优先语义角色、`aria-label`、`title` 和稳定属性，并包含产品真实支持的中英文名称。Files 曾使用 Explorer/资源管理器名称，兼容名称应集中维护，不能散落硬编码。
4. 可点击性必须同时满足：非隐藏、有尺寸、矩形位于当前视口内、中心点经 `elementFromPoint()` 命中自身或后代。不能点击屏幕外或被遮挡的同名元素。
5. 菜单操作必须原子化重试：“目标菜单项已出现则直接选择，否则点击 + 并重新等待”。不要假设前一个菜单的关闭动画已结束。
6. Browser 要在文件标签占满可见区域前验证；完成后显式重新激活 Files，再逐个验证文档。不能依赖标签的偶然排列或可见性。
7. 地址栏定位必须覆盖产品实际占位符 `Search or enter an address`，以及当前仍受支持的中英文变体；不能凭记忆编造文本。
8. Settings 可能是 `role="button"` 而非原生 `<button>`。通用点击器必须覆盖受控语义角色；进入对话框后，再用更窄的选择器寻找语言选项。
   左侧栏为窄模式时 Settings 触发器只显示图标，不渲染“Settings/设置”文字；自动验收应定位可见的 `button[aria-haspopup="dialog"]` 并等待 `[role="dialog"]`，不能用按钮文字作为唯一定位依据。
9. Puppeteer 连接 Electron 时使用 `defaultViewport: null`，并核对 `window.innerWidth` 与真实内容宽度，避免测试工具把窗口强制成 800×600 后制造布局假故障。
10. 首次失败立即保存失败步骤、截图、DOM snapshot、stdout、stderr、候选 DMG 标识和 run ID。修复前必须从这些证据解释根因，禁止靠增加任意 sleep 或盲目重跑掩盖竞态。
11. 动态新增用例先在最小夹具上验证定位器和完成条件，再并入固定流水线。断言应描述用户可见结果，不依赖 DOM 层级、元素序号、动画时长或只在某次构建存在的文本。
12. 自动脚本只能报告它真实观察到的能力。真实账号、模型对图片/Office/PDF 的语义理解、真实 WebSearch 和公司网络仍标为人工待验，不得由模拟登录或静态预览冒充通过。

执行顺序固定为：安装与启动 → 未完成授权窗关闭 → 模拟登录 → 进入工作台与工作区 → 模型/推理控件 → 时间上下文闭包与确定性夹具 → 侧栏 IM 入口和默认休眠 → 外观修改/恢复 → Browser 与错误恢复夹具 → 重新激活 Files → Office/PDF/图片预览 → 语言设置与 `DSH_HOME/settings.yaml` → 完全退出重启与持久化。新增动态用例插入最接近的阶段，并声明它依赖哪些前置状态；不要破坏后续步骤所需状态。

每个固定或动态步骤应可独立报告 `passed / failed / carried-forward / manual-required`。`carried-forward` 只允许用于同一候选 DMG 且已有截图和日志的阶段；下次新版本仍需把固定基线完整走一遍，不能把旧版本结果永久继承。

自动夹具若位于 macOS 临时目录，写入 workspace 存储前必须使用真实路径规范化（macOS 的 `/var` 通常解析为 `/private/var`）。否则产品的工作区安全校验会正确拒绝路径不一致；这属于验收夹具错误，不能误判为产品无法创建会话。

自动操作同名控件时，不能只用 DOM 元素“有宽高”判断可点击。右侧栏与已收起的底部栏可能同时保留同名按钮；脚本必须确认目标位于当前视口内，并用 `document.elementFromPoint()` 验证中心点击点没有被裁剪或遮挡。“新建标签页”必须按“目标菜单项已出现则直接选择，否则再点 +”作为一个原子重试动作，不能假设上一次菜单关闭动画已经完成。菜单未出现时同时保存点击后的截图和 DOM 快照，避免把误点或菜单时序问题误判为 Browser、Files 等产品功能失效。

若同一候选 DMG 已在某次 run 中完成侧栏、Browser 和全部文件预览，之后只因语言或重启阶段的验收脚本失败，可在复用该候选 DMG 时把 `acceptance_resume_run_id` 设为该证据 run ID。脚本仍执行安装、启动、登录、工作区和模型这些后续步骤的必要前置条件，但会把已有截图证明的侧栏、Browser、Office/PDF/图片结果标为从该 run 延续，只继续语言与重启阶段。不得用此参数跨产品源码、依赖、vendor bundle 或 DMG 哈希复用结果。

## 4. 真人固定基线

### 4.1 安装与首次启动

1. 校验 DMG SHA-256。
2. 安装到 Applications；未签名内部版用 Finder 右键“打开”。只有确认哈希正确仍被拦截时，才执行 `xattr -dr com.apple.quarantine "/Applications/锐捷 Harness.app"`。
3. 使用从未运行过本产品的测试账户启动。
4. 确认没有欢迎页、视图模式或模型选择新手引导。
5. 默认语言跟随 macOS；用户切换语言后立即生效并在重启后保持。
6. 在 Finder、Applications、Launchpad、Dock 和应用切换器检查主应用均显示紫色 RJ；另外必须实际观察 DMG 窗口标题栏的卷小图标、把 `.app` 拖入 Applications 时复制进度框的小图标，以及 Finder “应用程序”列表的 16/32 像素小图标，三处都必须是清晰的紫色 RJ，不能只依据 DMG 内的大图标放行。菜单栏检查黑白 RJ Template 图标在浅色、深色外观下均清晰并随系统反色。菜单栏黑白是 macOS 正确规范，不得误报为主品牌图标缺失；上述位置出现旧图标、Electron 默认图标或主应用黑白图标均算失败。
7. 图标验收使用新版本号生成的新 DMG，先弹出所有旧卷再挂载。若自动门禁已证明 `app.icns` 和 `.VolumeIcon.icns` 全部槽位正确，但某台机器仍显示旧图，记录截图和系统版本，重启 Finder 后再验。重启后仍错误则阻断，不得将“缓存”当作无证据的豁免理由。

### 4.2 登录、工作区、会话与模型

1. 用真实公司账号登录，检查浏览器回调页有锐捷 Harness 品牌和“可关闭并返回应用”提示；RJ 标记、完成勾与进度强调色应和应用图标保持同一蓝紫体系，不得显示旧红色。确认回调后先出现“正在验证账号”，验证完成后才出现“认证已完成”；若变慢，记录窗口究竟提示账号服务/网络慢，还是工作台组件初始化慢，并记录各阶段耗时、网络、代理和测试环境。用户可见文案应保持中性，不应针对某类硬件或运行环境下结论。
   在用户本轮明确授权的专用测试账户中，另做一次退出登录但不完成浏览器授权的取消路径：关闭浏览器后，实点等待窗左上角 macOS 原生交通灯，确认窗口真正消失、本次启动结束且不会再次自动弹出授权；不得只根据控件存在、变色或源码字符串判定通过，也不得出现 Windows 风格右上角“×”。认证服务当前异常时将该路径标为环境阻塞，禁止用日常账户强行重试。
2. 添加真实文件夹为工作区，新建会话并发送普通文本。
3. 确认模型选择器存在，默认值为 `deepseek-v4-flash / low`。
4. 在新会话询问“今天是几月几日、星期几？”，回答必须与 macOS 当前本地日期和星期一致，不能回答不知道、从新闻推断日期或使用模型训练年份。记录系统时区、问题、回答和截图。
5. 用真实模型询问“搜索今天 AI 圈发生的大事”，确认实际 `web_search`、`browser_search` 等工具参数都使用当前年份与当天/近期语义，并返回发布时间相符的非空来源；不得出现 2025、2024 等旧年份回退。不能以最终回答碰巧写对日期替代工具参数证据。此项与 4.5 的通用 WebSearch 连通性都必须通过。
6. 在一个曾包含错误旧年份的已有会话连续执行三次相对日期搜索，再新建无上下文会话重复三次；每次实际工具参数都应使用当前浏览器时区和当前年份，不能被早先错误年份锚定。来源缺失或混合时可以明确要求澄清，不能静默猜测。
7. 修改模型或推理强度，分别验证已有上下文和新建无上下文会话。
8. 完全退出再启动，重复日期问答并确认登录、工作区、会话和用户选择保持。认证服务异常或退出后可能无法重登时，不得擅自退出日常使用实例；把重启项记为“因环境阻塞”，等待专用测试账户或安全窗口。
9. 创建工作区 A、工作区 B 和至少三个可辨识会话，依次验证 A → B、未命名 → A、B → 未命名。拖动后会话内容与既有产物链接仍可用，原始工作目录没有改变；完全退出重启后侧栏归属保持，空工作区标题也能接收拖放。
10. 将一个会话归档，从“查看归档会话”恢复，确认回到原工作区；再归档并彻底删除另一个会话。普通会话 `...` 的彻底删除也必须可用。删除只移除会话记录，工作区内产物和共享附件仍存在。
11. 先打开一个已完成的历史会话，再切换到其他会话并删除前者；它必须被视为空闲会话并立即从侧栏消失。连续删除两个空闲会话，页面不得白屏、闪现登录页、重新授权或出现 `Failed to load plugins`。另起一个真实生成中的会话尝试删除，应提示先停止生成；停止后可正常删除。
12. 永久删除确认应显示为应用内 Modal，不得弹出浏览器/系统阻塞式 JS 确认框。删除当前会话后不要截图、切换页面或重新激活应用，立即依次验证：在默认新会话输入文字、重命名会话、重命名工作区、在目录选择器中新建文件夹；四处都必须首次点击即可出现光标并接受键盘输入。输入框中文字已选中但键盘无响应即判失败。
13. 在对话输入框及重命名输入框中右键，确认出现 macOS 原生编辑菜单并可执行撤销、重做、剪切、复制、粘贴和全选；分别粘贴普通文字与剪贴板图片。非编辑文本有选区时至少应能复制，空白非编辑区域不得被无意义菜单覆盖。

### 4.3 侧栏与文件预览

1. 展开、收起右侧栏。
2. 关闭 Files 标签，再通过“新建标签页”恢复。
3. 打开真实 `.docx`、`.xlsx`、`.pptx`、`.pdf` 和图片；至少一组使用中文文件名。
4. 检查内容可见、可滚动，Excel 不遮挡标签栏，所有标签可关闭。
5. 用损坏文件验证错误提示；用超过限制的 PDF 验证明确信息和下载回退。
6. 新生成文件应在约 2 秒内出现在 Files；“在文件夹中显示”必须交给 Finder。
7. 在新回合让真实模型用 Python 或终端生成一个中文文件名 PDF，并要求把文件交付给用户；轨迹中应实际调用 `dsh_im_return_file`，而不是只在最终回复里写文件名。
8. 工具显示 `Registered ... for IM delivery` 后，最终回复正文中的 PDF 引用和对话末尾“本次产出”必须同时可点击；两处点击都应在右侧栏打开并显示内容。正文若显示 `output/pdf/example.pdf` 这类相对子路径，也必须唯一解析到该轮记录的绝对产物路径。页面不得裸露 `:codex-file-citation{...}`，只证明磁盘文件存在或正文出现灰色普通文件名均判为失败。
9. 重新打开一个曾保存 `:codex-file-citation{...}` 的历史会话，原指令也必须转换成可点击的 DSH 文件引用；再用不存在的路径调用文件交付，必须保留真实错误且不得出现成功产物条目，兼容转换不能掩盖失败。
10. 主动打开并激活下栏终端、Files、Git 或浏览器，保持其中已有内容；随后从对话执行 `browser_search`、点击普通网页链接、PDF/文件正文引用及“本次产出”。这些对话或 Agent 发起的跳转必须全部在右侧栏打开，下栏内容与活动状态不被替换。
11. 再从下栏 Files 文件树或 Git 等面板内部主动点击文件/链接，确认它仍在下栏打开。即使同一资源已在下栏显示，随后从对话再次点击也必须进入右侧栏；关闭、收起、重新展开下栏后结果不变。
12. 在 Apple Silicon 和 Intel 构建闭包中分别打开下栏终端，确认 `zsh` 提示符正常出现，输入 `pwd` 和 `echo terminal-ok` 均有输出，关闭后重开仍可使用。检查日志与安装副本，两份 `node-pty/lib/unixTerminal.js` 都不得生成或包含 `app.asar.unpacked.unpacked` 路径。任一次出现 `posix_spawnp failed`、终端连接失败或空白输入区都必须阻断交付，不得因根目录另一份 `node-pty` 验证通过、开发机手工改过依赖或 Windows 终端正常而豁免。

### 4.4 图片和文档语义理解

使用真实模型分别上传或引用：图片、Word、Excel、PPT、文本 PDF、扫描 PDF。每个文件先放入一个只有测试者知道的唯一事实，例如编号、金额或一句话，再要求模型回答该事实。

通过条件：回答与文件内容一致；Excel 能定位指定工作表与单元格；扫描 PDF 能识别中英文；模型不能只复述文件名或声称成功却没有给出内容。记录提问、回答和截图。此项不能由模拟模型代替。

### 4.5 浏览器与 WebSearch

1. 地址栏打开普通 HTTPS 页面，确认页面实际渲染。
2. 验证返回、前进、刷新和 `target=_blank`。
3. 连续两次打开同一 URL，第二次仍真实加载。
4. 执行 `browser_search`，确认结果页进入右侧栏，并且同一次工具结果返回 `evidenceStatus: available`、非空来源与可供模型汇总的正文；不能只看 `delivered: true`，此前是否打开或激活过下栏不得改变目标位置。随后用 `browser_open` 打开一篇新闻并总结，再由测试者在右栏内点击另一篇新闻，要求模型通过 `browser_read_current` 读取当前页面并总结；三次回答都必须与右栏实际内容一致。
5. 用真实模型单独执行 `web_search`，确认工具仍存在、返回非空来源和原生引用卡片并能打开来源；“浏览器搜索增强”不得替换、隐藏或破坏独立 `web_search`。
6. 用自然提示词“联网搜索今天 AI 圈发生的大事”完成一次老板常用场景：查询参数采用当前日期；至少读取五个不同来源，其中包含官方来源和权威媒体；最终回答列出发布时间、交叉验证状态与可点击链接。只打开 Bing、只返回 `delivered: true`、只有搜索摘要没有读取来源，或没有真实来源却生成新闻，均判为失败。
7. 普通网络至少测一次；公司网络再测一次并记录代理/PAC。
8. 在可控网络或夹具中令主搜索源连续失败至少两次、备用方式随后成功；再令一个简单 Bash 调用直接失败、后续 Bash 或其他方式成功，以及 Pwsh 或文件渲染步骤失败后由另一方式成功：智能体必须换工具并完成任务。简单 Bash 的失败状态可能直接挂在工具行本身，主“对话”视图仍不得出现该中间失败行、红点、黄灯、红/黄错误文字或 `Error` 技术文本。切换到“轨迹”并检查日志时必须能看到原始失败、参数与后续替代路径，证明产品只是调整呈现，没有删除诊断事件。
9. 再令所有合理搜索方式都失败：此时专用回合终局错误必须仍按原产品行为出现，允许显示红色、错误文字和必要诊断，最终答复应简洁说明限制。下一条用户消息重新测试时必须重新计组，不能继承上一轮的隐藏状态。
10. 用可控夹具依次验证 Exa 成功、Exa 失败后 Tavily 成功、前序全部失败后 Firecrawl 成功；Firecrawl 未被需要时调用计数必须为零。正文读取先由本地引擎完成，只有本地无法正确提取或页面依赖 JavaScript 时才允许 Firecrawl 兜底。
11. 令所有搜索供应商失败但保持 Chromium 可联网：`browser_search` 仍应成功打开右栏，通过隔离 webview 的本地正文提取返回 `evidenceStatus: available` 并完成总结。主对话不得出现供应商名称、额度耗尽、限流、“联网搜索不可用”或中间红色错误；轨迹或日志必须保留原始诊断。再令 Chromium 页面也无法加载，确认导航仍不崩溃且不会把空白页伪装成已读取新闻。
12. 若本版宣称搜索费用从用户总额度扣除，在同一 SSO 测试账户中记录调用前后额度、请求 ID 和 GPTAuth 计量记录，确认费用只记到当前用户且失败/缓存命中不重复计费。若内部计费网关尚未部署，本项必须标为“未执行/因服务端阻塞”，不得用模型对话本身的 token 消耗冒充搜索供应商扣费。

如果 Chromium、Node 和系统浏览器都失败，先归类网络环境；如果只有 Harness 失败，归类产品缺陷。不得通过关闭 TLS、证书校验、webSecurity 或 sandbox 伪造通过。

### 4.6 内置外观与 IM 渠道

1. 全新 profile 不得要求从插件市场安装。左侧栏底部顺序应为账号/额度、“IM机器人”、设置；“IM机器人”与原生“设置”的文字颜色、行高和左边界一致，机器人与齿轮图标视觉尺寸一致；点击必须直达“插件 → IM机器人”，不得打开插件市场。收起后账号仅显示姓名首字并带与主图标一致的紫色底，机器人向左、向下的微调应使三个入口肉眼对齐，三个入口都必须正常响应；展开状态原有像素位置不得改变。展开侧栏顶部的锐捷字标与 `HARNESS` 标签在浅色、深色系统下都要检查；标签只能保留红色文字和边框，背景必须透明，深色下不得出现白色矩形底。外观位于“通用设置”顶部的“界面外观（颜色、壁纸与透明度）”；先分别在浅色和深色模式下确认首次启动的用户气泡是各自对应的原版颜色，再把“主色”改为鲜明且与默认差异明显的颜色，按钮、链接、选中态和用户气泡都应立即跟随。随后点击“一键恢复默认”，必须撤销气泡颜色覆盖并回到当前系统浅色/深色主题对应的原版颜色，重启后仍正确；恢复默认不得退出登录或清空会话、工作区与 IM 配置。Mac 主窗口始终保留左上角原生交通灯和自然连续的标题栏材质；切换全部外观预设时不得出现 Windows 右上角按钮、固定色矩形或遮盖主题背景的标题栏块。
2. 不进入 IM 设置，静置 60 秒：微信、飞书、钉钉、企业微信、QQ、Slack、Telegram、Discord、WhatsApp 均不得打开浏览器、弹授权窗/二维码或反复提示缺少凭据；条件允许时保存外部网络抓包。
3. 主动进入“设置 → 插件 → IM机器人”，逐一确认九个渠道入口存在。选择一个非飞书渠道点击添加/接入，确认只有此时才出现该渠道的扫码、Token 或凭据说明；取消并关闭后不得自动重开，其他渠道不得被连带启用。
4. 使用专用飞书机器人完成主动接入、连接测试、发消息和接续现有 Harness 会话；执行 `/new`、`/sessions`、`/sessions <关键词>`、`/status`、`/ws`、`/cd` 和 `/stop`，从 `/sessions` 接续至少一个由桌面端或 CLI 创建的已有会话，确认不同聊天、话题和工作区不串线。触发一次模型提问、计划或工具授权卡片，核对允许/拒绝回到原会话，转发卡片不得控制原会话；再按发布范围至少抽测一个其他渠道。停用或删除连接后应停止连接，但不影响桌面聊天和其他渠道。
5. 测试应用应按场景限制 `senderAllowlist`、`groupAllowlist`、`approvers` 与 `workspaceRoots`。所有 Secret、Token、二维码和个人账号信息必须从截图与报告中遮盖；尚未配置组织凭据时记为“待部署配置”，不能误报插件缺失。控制范围是 Harness 会话和任务，不是任意删除或篡改平台历史消息。
6. 用户主动选择 WhatsApp 后验证二维码生成与扫码连接；再分别在断网或无效测试代理下实际点击“生成二维码”，确认应用不退出、不重启，IM 页面仍能关闭错误并继续操作。失败时只能显示可读的网络/代理说明，不得出现 `ReferenceError`、`invalid_union`、`invalid_value` 等内部异常或校验 JSON。恢复网络后无需清除 profile 即可重试；无代理网络仍须正常，系统代理不可用时应用本身仍能启动。

通过条件：最终 `.app` 开箱包含外观与九渠道 IM 能力，不要求员工从插件市场安装；外观无需外部配置，IM 仅在用户主动选择渠道后要求对应组织或个人配置。重启后外观设置、IM 实例设置与 Harness 会话映射保持。

### 4.7 升级与全新重建

本节只能在用户本轮明确授权的专用测试账户执行。不得删除日常使用账户的真实 `~/.dsh`，也不得因本指导存在就自行卸载或覆盖用户当前应用。

1. 保留旧版数据升级：登录、历史会话、模型/推理强度、市场来源、插件和安装回执不得丢失。测试 profile 应预先包含一个会实体化 `@deepseek-ai/cordis`、`dsh-scope`、`dsh-system-prompt` 等 peer 依赖的无害插件或固定夹具；该插件无需连接外部服务，也不要求配置 API key。
2. 启动后检查日志不得出现 `duplicate deployment:persona`，并依次确认历史会话可打开、模型选择器可操作、新建对话有响应、已有或新工作区可选择。插件包、配置和回执仍须存在；框架包则应解析到当前 `.app` 的同一物理实例。
3. 上述 profile 迁移用例只判断本地启动和交互链路。真实模型发送、账号额度和 WebSearch 仍分别按 4.2、4.5 验收；短暂 HTTP 503 或外部服务不可用不得误报为 profile 单例回归。
4. 在另一个专用测试账户完全退出应用后删除该账户的 `~/.dsh`，再次启动一次：profile 与 `settings.yaml` 应自动重建。必须等待工作台、模型选择器和工作区入口出现后再判定，不用固定 sleep，也不要在应用运行中反复删除目录制造文件句柄竞态。
5. 全新 profile 默认启用 `DSH 1024Store`；已有来源配置（包括空数组）升级时不得被覆盖。
6. `profiles/desktop/node_modules/dsh-better-sidebar` 与安装闭包内的 `@deepseek-ai/*` 框架包必须指向新版应用依赖，不能加载旧实体副本。

### 4.8 应用内更新与 curl 安装

本节涉及覆盖 `/Applications`，只能在用户本轮明确授权的专用测试账户执行。线上版本接口与两个下载入口必须按 `04-自动更新服务器交接.md` 先完成文件和哈希校验；禁止为测试先提高线上版本号再补文件。

1. 验证三个固定地址：版本接口返回 HTTP 200、`application/json` 和规范稳定 SemVer；Mac 下载入口最终返回本版 DMG；Windows 下载入口也必须已有同版本 EXE。记录重定向链、字节数、SHA-256 和缓存响应头。
2. `2.1.0` 是首次启用更新的桥接版，`2.0.7` 无法自动升级。对 `2.1.0` 只验证手动或 curl 安装、托盘“检查更新…”可用、服务端同版本时不提示降级。第一次真实跨版本更新必须在 `2.1.1` 发布时使用保留的 `2.1.0` 正式安装副本完成；没有兼容旧版时标为“未执行”，不得伪造通过。
3. 在兼容旧版正式 `.app` 上启动并等待约 60 秒。发现更高版本时应出现原生提示；选择“稍后”或关闭后，同一版本不得在后续后台轮询中反复弹窗，托盘“检查更新…”仍应允许主动重新打开提示。
4. 接受更新后不应出现保存路径选择框；DMG 自动下载到 Electron userData 的私有 `updates` 目录。下载中托盘显示状态，完成后系统打开 DMG。断网、HTTP 错误、空文件、超过 1 GiB 或无效 DMG 都不得破坏当前应用，恢复网络后可从托盘重试。
5. 应用内流程不会静默替换 `/Applications`。退出旧应用，把 DMG 中的新应用拖入 Applications 覆盖，重新打开并确认版本提升；登录、历史会话、工作区、模型/推理强度、市场来源、插件和设置全部保留。启动后按提示选择删除或保留已下载 DMG，选择应生效且不重复询问。
6. 验证网站脚本内容与仓库 `scripts/install-macos.sh` 一致，然后在另一专用测试环境先退出应用并执行：

   ```bash
   curl -fsSL https://gptauth.ruijie.com.cn/harness/install.sh | bash
   ```

   脚本必须下载当前 DMG、通过 DMG 与 bundle id 校验、安装到 `/Applications/锐捷 Harness.app`，并在无写权限时正常请求管理员密码。应用仍在运行、DMG 损坏、bundle id 不符或复制失败时必须拒绝或恢复旧应用，不能留下半个 `.app`。脚本不得清除 quarantine 或关闭 Gatekeeper；未签名内部版首次启动仍使用 Finder 右键“打开”。

通过条件：更新发现和拒绝路径不骚扰用户；接受后自动下载并打开正确 DMG；人工覆盖或 curl 安装后版本和用户数据正确；三个线上入口不会跨平台错版。macOS 未签名内部版不得描述为完全静默自动安装。

## 5. 结果与阶段放行判定

每项只允许：`通过 / 失败 / 因环境阻塞 / 未执行`。失败和未执行不能写成“全部通过”。证据至少包含操作截图、必要日志、实际结果、期望结果和环境信息。

通过率只用于描述覆盖情况，不能机械地决定放行。验收者必须同时判断失败性质、影响范围、发生概率、是否涉及核心链路、数据/安全风险、是否有清晰规避方式，以及尚未执行的项目是否足以改变结论。最终只能给出以下两种阶段结论之一：

| 阶段结论 | 判定条件 | 后续动作 |
|---|---|---|
| **允许进入下一步** | 全部通过，或仅有低影响瑕疵、已证实的验收器误报、暂时性外部环境问题；核心安装、启动、数据、登录、工作区、会话和主要交互没有被破坏，剩余风险可在真人测试中有效验证 | 交付候选 DMG 给真人测试；报告中列出所有例外、规避方式和下一版建议。不得把“有条件放行”写成“全部通过” |
| **阻断，不进入下一步** | 存在崩溃、无法启动、数据丢失/损坏、安全风险、旧数据升级失败、核心流程不可用、大范围回归，或证据不足到无法合理排除这些风险 | 保留云端 candidate 和证据，不下载作交付、不安排真人重复验证已知阻断问题；先提交完整报告与问题清单，等待用户决定是否开启源码修复和重新打包的新一轮任务 |

低影响瑕疵可以包括不阻断主要目标、不会造成数据或安全后果、具有明确规避方式的视觉或次要交互问题。验收者必须写出为何“瑕不掩瑜”的证据，不能只凭通过项数量压过关键失败。未知根因、偶发但可能损坏数据的问题按阻断处理。

自动验收结束时先作“是否允许进入真人测试”的判定；真人验收结束时再作“是否允许内部上线/发布”的判定。自动阶段放行只能称为“允许进入真人测试的 Mac 候选包”，不能提前称为正式可用版。

允许称为“Mac 内部可用版”时，应满足：DMG 哈希与架构正确；至少一台 Apple Silicon Mac 完成固定基线；动态增量与相邻影响均有结论；真实模型附件理解与真实 WebSearch 已验证；更新接口、应用内更新适用路径和 curl 安装状态有明确证据；没有发布阻断问题。低影响已知问题可以随版本发布，但必须在报告中公开记录其影响、规避方式和延后理由。

验收报告第一段只写：验收对象、已执行范围、通过/失败/阻塞/未执行数量，以及“允许进入下一步”或“阻断，不进入下一步”。不要在开头写“去修源码”或把下一轮方案混进验收结论；根因、问题清单和建议放在后续独立章节。

## 6. 失败后的闭环

先完成当前可安全继续的验收项并保存首个失败步骤、时间、截图、DOM snapshot、stdout/stderr、候选 DMG 哈希、run ID 和环境。不要因为一个非破坏性失败立即结束整套验收；只有继续执行会污染状态、破坏数据或让证据失真时才提前停止。随后判断属于产品源码、打包闭包、Mac 平台、验收脚本、账号服务还是网络环境：

- 产品源码、依赖、vendor、打包闭包或 Mac 平台问题：记录根因、影响、复现步骤和建议，把本轮报告写完并作阶段判定。验收者不得直接修改产品源码、切分支或重新打包；向用户说明阻断点并等待其授权下一轮修复。若问题经证据判为低影响，也可以有条件放行，但必须保留已知问题。
- 仅验收脚本定位、断言或时序错误：这属于验收工具自身修正，可以保持同一候选 DMG，先在最小夹具验证修正，再按打包指导复用 candidate 续验。修正验收器不能改变产品预期或放宽断言来制造通过。
- 环境问题：换普通网络、干净账户或另一台 Mac 交叉验证，保留原环境记录。

同一候选的续跑应从**最近一个有报告、截图和日志共同证明通过的可信断点**开始，而不是默认从头重跑；重新建立后续步骤必需的最小登录、窗口或工作区状态即可。断点之后的失败项、未执行项及其依赖项必须全部重跑。只有候选 DMG 哈希、产品源码、依赖、vendor 和打包配置完全未变时才能继承；任一变化都创建新候选并从固定基线开始。禁止仅凭“上次好像通过”跳过，也不能因验收器修正而抹掉原失败记录。

本轮验收结束后先产出完整报告和两态结论，再决定是否交付下载。源码修复、版本调整和重新打包只写成下一轮建议，等待用户确认；这样验收不会在中途悄悄变成开发任务。

## 7. 每次使用结束后的按需优化

验收结束后必须审查本文件，但不要求机械修改。仅在以下情况更新：

1. 本次发现了可复现的新故障，并已有明确根因、稳定修复与验证方法。
2. 新功能以后每版都必须保留，应加入固定基线。
3. 某个动态映射漏掉了真实相邻风险，应补充动态规则。
4. 路径、命令、证据名称或发布判定已经变化。
5. 某条步骤含糊，导致不同执行者得到不同结论。

一次性网络抖动、未经证实的猜测和只属于某台电脑的偶发现象留在当次报告，不写成永久规则。更新后执行 `git diff --check`，确认没有与另外两份指导冲突，并把有价值的经验与对应源码或测试一起提交。
